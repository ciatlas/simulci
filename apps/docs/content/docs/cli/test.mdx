---
title: simulci test
description: Run the route tests under .github/simulci/tests.
---

```sh
npx simulci test [files...] [flags]
```

Runs every `*.test.yml` or `*.test.yaml` under `.github/simulci/tests` (or the files named) against the checkout's workflows. The
[test file format](/docs/reference/test-files) says what a case asserts.

| Flag                    | Does                                                                                   |
| ----------------------- | -------------------------------------------------------------------------------------- |
| `--dir`                 | the checkout; default `.`                                                              |
| `-t`, `--filter`        | runs only the cases whose name contains the text                                       |
| `-u`, `--update`        | writes every snapshot and removes the stale ones                                       |
| `--ci`                  | writes no snapshot unless `-u`, fails on a missing one, rejects `only`; default when `CI=true` |
| `--strict`              | ignores `allowMaybe`; a stale snapshot fails                                           |
| `--snapshot-detail`     | `steps` (default) or `legs`: the detail snapshots record                               |
| `--junit <file>`        | writes a JUnit report                                                                  |
| `--annotations`         | prints GitHub annotations; default when `GITHUB_ACTIONS=true`                          |
| `--assume`              | a mock for every case; repeat it for more                                              |
| `--assume-file <file>`  | a YAML list of mocks for every case                                                    |
| `--remotes`             | `lock` (default), `fetch` or `off`: how remote workflows and actions are read          |
| `--offline`             | reads remotes only from the cache; default when `SIMULCI_OFFLINE=1`                    |
| `--api-url`             | the GitHub API; default `GITHUB_API_URL`, else `https://api.github.com`                |
| `--repository`          | the checkout's `owner/name`; default `GITHUB_REPOSITORY`, else the `origin` remote     |
| `--github-com`          | on GitHub Enterprise Server, reads what it lacks from github.com                       |

`--assume` and `--assume-file` take [assume entries](/docs/reference/mocks); they win over the file's and the case's.
The remote flags are [`simulci plan`'s](/docs/cli/plan#remotes). Remotes are read once, before any case runs.

## Results

```text
.github/simulci/tests/ci.test.yml → ci.yml
  ✓ a pull request tests but never deploys
  ✓ a docs-only push starts nothing

2 passed · 0 failed · 0 invalid · 0 skipped · exit 0
```

A case passes, fails, is invalid (it cannot be checked: a schema error, a unit path that names nothing, a mock
conflict) or is skipped. The exit code is `0` when nothing failed, `1` when a case failed, and `2` when anything is
invalid, there are no test files or no workflows, a test file sits under `.github/workflows` (GitHub would run it),
`--snapshot-detail` is not `steps` or `legs`, or an `--assume` entry or the `--assume-file` cannot be read.

It is also `2`, before any case runs, when a pinned remote cannot be read or no longer matches its digest, or
`remotes.lock.yml` or `actions.lock` cannot be used: the plans would differ from GitHub's, so no verdict is given.
`--remotes fetch` with `--ci` (or `CI=true`) exits `2` too: a tag that moves would change the verdict of the same
commit. Pin remotes with `simulci remotes update` instead. Any other
error (a `--junit` file it cannot write) also exits `2` with its message, so `1` always means a case failed;
`SIMULCI_DEBUG=1` prints its stack as well.

## Snapshots

A case with `snapshot: true` records its workflow's whole plan in `__snapshots__/<file>.snap.json` beside the test
file (`ci.test.yml` → `__snapshots__/ci.test.snap.json`), with its other assertions or instead of them.

- Locally, a missing snapshot is written; a changed plan fails with a line diff. `-u` accepts the change.
- With `--ci`, a missing snapshot fails: run `simulci test -u` and commit it.
- A stored snapshot whose case is gone is reported; `-u` removes it, and with `--strict` it fails.

## In CI

In GitHub Actions each failure is annotated twice: an error on the test line, and a notice on the workflow line
that decided (at most ten of each). `--junit` writes one `<testsuite>` per file and one `<testcase>` per case. The
[GitHub Action](/docs/action) runs the tests this way and adds a job summary.
