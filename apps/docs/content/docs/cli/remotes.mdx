---
title: simulci remotes
description: Pin the remote workflows and actions a repository uses.
---

```sh
npx simulci remotes update [flags]
npx simulci remotes check [flags]
```

`plan` and `test` read another repository's reusable workflow or action at a pinned commit. `remotes update` writes
the pins to `.github/simulci/remotes.lock.yml`, which you commit; `remotes check` tells whether they are current.
Moving a remote is then a one-line diff, and the same commit always gives the same plans.

## update

Resolves every remote the checkout reaches, workflows called from remote workflows included, reads each file and
writes the lockfile: per remote, its commit, the file read and a sha256 digest of it. It prints what was added,
changed and removed. Running it again with nothing moved writes the same bytes.

A remote it cannot read keeps its old entry; one that never had an entry goes under `unreadable`. It then exits `1`.

## check

Exits `0` when the lockfile is current, `1` when it is not, and `2` when it cannot tell. It checks that:

- every remote the checkout reaches has an entry, and no entry is unused;
- no entry disagrees with `.github/workflows/actions.lock` or a full-SHA ref;
- each pinned file still has its digest (with `--offline`, only the lockfile is checked).

Each problem is printed with the lockfile's line. A checkout with no remotes needs no lockfile.

## Flags

| Flag           | Does                                                                                     | Command        |
| -------------- | ---------------------------------------------------------------------------------------- | -------------- |
| `--dir`        | the checkout; default `.`                                                                | both           |
| `--api-url`    | the GitHub API; default `GITHUB_API_URL`, else `https://api.github.com`                  | both           |
| `--github-com` | on GitHub Enterprise Server, reads what it lacks from github.com                         | both           |
| `--offline`    | checks the lockfile only, not the files; default when `SIMULCI_OFFLINE=1`               | `check`        |

The token is read as [`simulci plan`](/docs/cli/plan#remotes) reads it, and never printed.

## Modes

`--remotes` on `plan` and `test` says what is read:

| Mode   | Reads                                                                      |
| ------ | -------------------------------------------------------------------------- |
| `lock` | commits pinned by a full-SHA ref, `actions.lock` or the lockfile (default) |
| `fetch`| as `lock`, and resolves every other ref to the commit it is at now         |
| `off`  | nothing: every remote call stays open                                      |

In `lock` mode a remote the lockfile lacks is not read, with a warning. `simulci test --ci` refuses `fetch`.
